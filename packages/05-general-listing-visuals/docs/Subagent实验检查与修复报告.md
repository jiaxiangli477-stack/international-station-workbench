# Subagent 实验与修复结论

## 结论

三个独立subagent分别审查资料提取／属性流程、图片命名与旧上传器、总体可执行性；主代理复核并修复。最后由总体审查者锁定四脚本SHA256完成独立复审。

当前可用于本地Agent资料实验、结构化属性准备、图片交接清单检查，不能认定已经可以自动完成真实国际站上品。真实填写、图片上传、草稿保存和回读未执行；新通用包仍没有完整通用平台执行器，旧上传器不能直接代替。

## 实际做过的实验

| 环节 | 实际结果 | 范围 |
| --- | --- | --- |
| 原始资料提取 | Subagent实际读取虚构TXT公司／商品资料，保留两版规格冲突，剔除另一SKU报价 | Agent完成，不是通用自动文档解析器 |
| 标题与卖点 | 生成3条身份型标题候选与1条资料可支持的卖点草稿 | 未编足固定条数；无真实页面限制与用户确认时不标已批准 |
| 缺资料门禁 | 缺公司确认、实际类目结构或必填值时阻断；不能把候选直接当填写值 | 来源文本与确认标记仍需真实人工／Agent核对 |
| 正向本地链路 | 虚构完整输入经过prepare、build_plan、image_inventory三个真实CLI，均exit0；生成1项字段计划、1张主图和1张详情图的文件清单 | 图片为绘制的测试夹具，未生成功能性商品成品图，无业务平台访问 |
| 错误回归 | 主控新增20项测试、既有8项测试通过；旧上传器17项断言包含缺陷复现，不计作上传成功 | 各项结果文件在审查实验目录 |
| 最终独立复审 | 未发现阻止当前本地实验的剩余阻塞缺陷，已锁定四脚本哈希 | 不等于生产安全审计、视觉或平台验收 |

## 已修复和新增

- prepare拒绝非字符串来源、冲突、跨SKU字段、空白值及非有限数；保留来源记录，CSV转义可能的公式值。仅作基础复核。
- build_plan校验真实类目配置结构、当前SKU字段、必填与选填、下拉已见选项、字符／数值上限、条件启用及未知约束；异常有结构化阻断。它不是浏览器执行器，也不验证来源真实性。
- image_inventory以显式SKU生成带顺序、尺寸和哈希的清单；拒绝不规范名称、多个候选目录、缺映射、缺号、重复、损坏、全透明、格式不符等。图片身份和视觉检查仍pending。
- render拒绝全透明输入和错误输出扩展名。它仍只是中性预览排版。
- 两Skill和资料文件夹新增成品交接规则与实验步骤，类目模板补足新接口字段。

## 主图与详情图名称

每款产品单独目录：

成品图片/<产品标识>/主图/m1.png、m2.png……m6.png
成品图片/<产品标识>/详情页/d1.png、d2.png……
成品图片/<产品标识>/detail-map.json

本工具主图约定最多6张，实际不凑数，仍需满足当前页面要求。详情图的模块和整体顺序由detail-map明确，不能只凭d1/d2猜用途；d10等可由新本地清单识别，但旧上传器会漏掉。原始图片保留原名，预览和草稿不放成品目录。

## 原上传器问题（原分发包未修改）

CLI参数二次偏移、字典序截取前六、草稿／重复／损坏文件被选中、详情命名文档与正则不一致、静默漏图，以及未回读上传结果等均有本地重现。旧模块数字值只属历史代码，不当当前所有类目事实。新包没有偷偷接入这些有缺陷的上传行为。

## 下一步真实实验条件

需要一款真实产品的授权资料、确认的公司信息和当前选好类目的发布页URL／页面证据；完成确认后，现场验证控件、字段回读、图片模块及真实上传结果。保存草稿／正式发布按具体授权执行。不以本地清单ready或旧日志“完成”代替最终结果。
