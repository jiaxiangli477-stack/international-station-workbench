# 阿里巴巴国际站通用上品与商品视觉 Skill

平台固定为阿里巴巴国际站，行业和公司资料可替换。包含两套配合使用的 Agent Skill：

- `b2b-listing-assistant`：资料收集、公司配置、属性准备、标题与卖点候选、本地字段及图片交接检查。
- `b2b-product-visuals`：品牌和素材配置、主图与详情页规划、图像制作及复核工作流程，附真实照片基础预览工具。

**当前是通用工作流程和本地辅助工具，不是已经验收的“一键上架软件”。**真实浏览器填表、图片上传、草稿保存及回读尚需针对具体类目完成适配；原视觉包全部模板和批量制作能力也未完整迁移。

## 1. 下载和放置

下载本目录的 `通用上品与商品视觉Skills.zip` 与 `资料准备文件夹模板.zip`，解压到自己的 D/E 盘工作目录。两个 Skill 文件夹应完整保留，主入口为各自的 `SKILL.md`。

可以先直接向支持本地文件的 Agent 提供这两个 SKILL.md 的绝对路径，请它阅读并按规则工作。仅解压文件不代表客户端已自动发现或激活 Skill；自动发现须按所用客户端的实际安装方式配置。本包未附 Python 便携环境或浏览器运行时，也不修改系统配置。

本机已有安装位置是 `D:\Codex\skills\b2b-listing-assistant` 与 `D:\Codex\skills\b2b-product-visuals`，发现入口位于 E 盘；其他人以自己的安装位置为准。

## 2. 第一次怎么开始

可复制给 Agent：

> 请读取通用上品助手和通用商品视觉的 SKILL.md。平台固定为阿里巴巴国际站，请一次性提供资料准备文件夹模板和完整清单。读取我提交的资料后，先核对类目发布页结构，再整理公司与产品事实；有缺项或冲突请集中反馈，摘要经我确认后保存成该公司的专属参考资料。

Agent不重复询问平台或市场，也不拆成很多轮零碎问答。使用者无需自己写 Markdown、JSON 或专业属性表。

## 3. 资料文件夹里放什么

解压资料模板后，把最外层文件夹改成公司名，每个目录都有“放什么-说明.txt”，根目录有 `00-使用说明.html`。

| 目录 | 内容 |
| --- | --- |
| 01-公司介绍与业务能力 | 公司名称、角色、介绍、品牌及可证明能力 |
| 02-类目发布页 | 每类目的发布页 URL、类目路径、字段和下拉截图 |
| 03-产品资料 | 每款的规格、说明书、实拍、标签、报价、包装和交期 |
| 04-品牌与视觉规范 | Logo、颜色、已有规范和图片要求 |
| 05-按需展示的真实素材 | 本次需要展示且有证据的资质、公司/工厂、客户案例等 |
| 06-FAQ与风格参考 | 已有问答、确认的政策及风格参考 |
| 07-标题关键词与文案参考-选填 | 旧标题、关键词、禁用词、卖点或详情文案参考 |
| 99-其他现成资料 | 不方便拆开的整套材料 |

多个类目复制类目目录，多个产品复制产品目录并标明对应关系。先做一款代表产品即可。没有的写“待补”或“不适用”，无法公开的注明范围。标题和卖点由Agent按确认资料生成，旧稿只是选填；没有资质、工厂、案例或评价时不启用对应展示模块。页面实际必填的数据缺失时，仍须补齐或暂停相应步骤，不能编造。

## 4. 发布页截图怎么提供

1. 在国际站选好具体产品类目，再复制真实发布页 URL 和页面显示的类目路径；不猜类目 ID。
2. 展开“其他属性/更多属性”，从上到下分段截图，拍清字段名、必填标记、单位、提示与字符限制。
3. 下拉框展开；搜索型下拉还要搜索本产品对应值并拍结果，联动字段先处理前置选择。默认几项不是完整选项表。
4. 交易、价格阶梯、发货物流、详情与图片模块按实际页面提供。Agent能直接读取当前已授权页面时不用重复截图。

去掉链接中的会话凭据，截图不带无关订单、账号和客户隐私。页面证据说明平台填什么；产品资料说明值是什么，两者分别核验。

## 5. 资料如何保存和复用

Agent统一读取后，将来源、已确认值、冲突、缺少及不适用项汇总供用户确认，再在当前 Skill 中按需建立：

```text
references/companies/<公司标识>/
  company.md
  category-rules.md
  business-rules.md
  visual-guide.md
  sources.md
  readiness.md
  products/<产品标识>.md
```

通用类目结构放在 `references/categories/<类目标识>/`，公司专属规则引用其版本。不同公司独立存放，商品价格和参数按SKU记录，不能沿用上一家公司或另一款产品的值。后续复用有效资料，只补变化；两套Skill复用同主体资料时核对来源、版本和授权。

**通用公开包排除公司专属参考目录。**真正填入业务资料后留在本地或授权范围内，不要把登录凭据、客户隐私或私有材料推到公开仓库。

## 6. 主图和详情图命名

原始产品照片无需强制改名；制作并确认的成品按单产品交接：

```text
成品图片/<产品标识>/
  主图/m1.png
  主图/m2.png ... m6.png
  详情页/d1.png
  详情页/d2.png ...
  detail-map.json
```

主图从 m1 开始连续编号，本地工具约定最多6张，按需提供不凑数；页面数量、尺寸和文件体积要求另核实。详情图通过 `detail-map.json` 明确实际页面模块和整数顺序，由Agent整理；文件名不自动证明图片用途。不要把草稿、预览、同编号多版本或其他SKU放入成品目录。

旧上传器固定分组和历史模块数字ID不能直接视为当前类目事实，也不支持直接消费新清单。

## 7. 本地辅助工具

字段脚本使用 Python 标准库；图片检查与预览还需要 Pillow。本轮在现有 Windows/Python 环境运行，未做全新电脑免安装验收。若本机缺依赖，应按自己的项目环境配置，不必全局安装或升级。

在配套上品 Skill 目录运行，输入输出路径请换成自己的 D/E 盘绝对路径：

```powershell
python scripts/prepare.py --input D:/工作目录/完整输入.json --output D:/工作目录/基础复核
python scripts/build_plan.py --input D:/工作目录/完整输入.json --output D:/工作目录/字段计划.json
python scripts/image_inventory.py --image-dir D:/工作目录/成品图片/产品001 --product-id 产品001 --mapping D:/工作目录/detail-map.json --output D:/工作目录/图片清单.json
```

在商品视觉 Skill 目录可运行：

```powershell
python scripts/render.py --photo D:/工作目录/真实照片.png --output D:/工作目录/中性预览.png
```

- `prepare.py`只做基础字段和来源标记复核，输出CSV/JSON。
- `build_plan.py`需要包含公司、产品、属性和已核实页面结构的完整输入，校验SKU、必填、选项及支持的限制；**不能把 prepare 输出的 review.json 直接当作它的输入。**
- `image_inventory.py`检查文件命名、顺序、映射、解码、透明、格式和哈希；视觉及SKU图像身份仍待人工/Agent核对。
- `render.py`只做真实照片等比例中性排版预览，不是完整主图详情页生成器。

输入由Agent读取原资料后按 Skill 参考格式整理。脚本不会自动理解任意PDF/Excel，也不会验证来源真实性。详细接口见两套 Skill 的 references 文档。

## 8. 怎样理解检查结果

`needs_input` 或 `blocked` 表示有待补或异常；`ready_for_review`仅基础复核；`ready_for_local_review`仅本地字段或文件计划通过。所有本地状态都不表示已上传、保存或可正式发布。

接下来应选一款真实产品，在实际类目页面核验控件与字段回读、上传结果、授权草稿保存及保存后回读。正式发布需明确授权。
