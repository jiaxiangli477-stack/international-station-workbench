# 通用Skill：主控、sub skill与参考资料的文件级拆解


## 1. 入口先交模板，让使用者填写并保存

首次、换公司或未配置时，上品主控先读template-delivery.md，再实际调用init_workspace.py复制空白母版并打包，把填写目录、ZIP和说明的具体链接直接给使用者。使用者按文件夹放资料、填写状态说明并保存副本，完成后交整个目录／ZIP或授权路径。不能只列问题，也不能让人编辑Skill的母版。

Agent统一读取→核实页面结构与产品事实→集中反馈缺口和冲突→用户确认摘要→调用save_profile.py把整理后的事实保存到公司专属参考并读回。填好工作区与参考已确认是两个状态；保存参考也不是平台已保存商品。已有有效同公司配置先复用，换公司再生成新副本。

## 3. 四个上品sub skill的调度契约

| 子入口 | 触发时机 | 输入 | 需读取 | 输出 | 实现状态 |
| --- | --- | --- | --- | --- | --- |
| title-scout | 产品身份与页面限制足以支持候选时 | 主控确认资料、当前页面限制、选填关键词 | references/title-rules.md | 标题候选＋字符数＋来源＋风险与推荐 | Agent规则；原生成与清洗程序未移植 |
| selling-points | 产品及适用公司能力确认后 | 同SKU事实、公司证据、当前页面格式 | references/evidence-to-copy.md | 逐条卖点草稿＋证据表＋未解决项 | Agent规则；原自动生成程序未移植 |
| price-filler | 准备价格、起订量及阶梯时 | 当前SKU已确认报价、币种、单位、MOQ和阶梯 | references/pricing-rules.md；references/quote-input.template.json | 原报价计划＋缺口／复核提醒，不补算遗漏价格 | 有prepare_pricing.py本地校验；无通用页面填价 |
| image-upload | 视觉分支给出确认成品后 | 当前SKU成品目录、detail-map及真实页面模块证据 | ../../references/image-handoff.md；references/upload-gates.md | 文件、顺序、模块、哈希、错误及待验状态 | 调度image_inventory.py；无通用浏览器上传器 |

标题与卖点返回的是候选。价格模块返回未被改造的确认报价计划；MOQ与首档数量不一致时列待复核。图片模块返回文件清单。主控统一核对来源、版本、SKU及用户确认，不让子模块自行填入公司能力、交易条件或未经核实参数。


## 4. 上品主控具体读哪些references

| 文件（references/下） | 什么时候读 | 会改变哪些执行决定 |
| --- | --- | --- |
| template-delivery.md | 首次／换公司入口 | 调用模板导出脚本、直接给具体文件链接；用户保存并交回后，确认再入库。 |
| company-onboarding.md | 发模板时及收到材料后 | 一次性清单、原模块需要哪些资料、集中缺口反馈、必备和选填。 |
| category-page-intake.md | 建立新类目配置前 | 发布页URL、分区截图、展开属性、搜索型下拉与联动的证据要求。 |
| category-fields.template.json | 整理页面结构时 | 空白字段结构：key、标签、控件、必填、选项、限制、依赖与证据；默认不确认。 |
| company-profile.template.md | 用户确认摘要后 | 公司参考的整理框架，不是预填公司事实。 |
| product-evidence.md | 读取当前产品资料时 | 按实际类目记录值、单位、适用条件、来源、状态与冲突。 |
| input-schema.md | 主控分派子任务时 | 公司、单SKU、页面字段和各子模块的输入输出契约；草稿不可自动转确认。 |
| input.example.json | 组织基础复核输入时 | 只有空白输入结构，具体公司名、产品名、报价和类目均不预填。 |
| compliance-review.md | 生成前与汇总交接前 | 主体、SKU、证据范围和图文交易的一致性；风险与缺口怎样处置。 |
| local-experiment.md | 运行本地程序时 | 完整输入、各脚本状态、支持限制与未实现的平台执行边界。 |
| image-handoff.md | 接收视觉成品时 | 单SKU成品目录、文件名、详情模块映射、顺序与图片检查范围。 |


## 5. 视觉侧：只有Codex原生生图入口

视觉Skill仅含SKILL、六份通用reference和空白TXT模板／ZIP；不包含scripts、Python、HTML/CSS制图模板、外部接口或旧业务板块。独立使用时直接给assets内模板链接，不调用上品的模板导出或保存脚本。

| 文件 | 时机 | 作用 |
| --- | --- | --- |
| intake.md | 先收资料 | 一次给产品、实拍／概念、事实、风格与输出清单 |
| product-library.md | 索引产品库 | 文件名、子目录与图中文字交叉核对，冲突项不进生图 |
| b2b-planning.md | 规划B端图文 | 围绕采购判断组织，不复用旧私有板块和模板 |
| native-image-generation.md | 调用原生工具 | 先看编辑目标，正确传入参考图，只走当前原生工具 |
| review-and-delivery.md | 看图与交付 | 核对实物、文字、事实和真实输出；记录路径与待验项 |
| company-memory.md | 确认后复用 | 宿主文件工具保存新公司的必要参考，不附业务预设 |

图片输入支持实拍、命名产品库、图中文字名称，以及明确要求的新概念图；实际生成后逐图核对。不依赖上品Skill才能启动。

## 6. 空白母版、填写区、参考库不能混

assets/intake-folder-template：反复复用的空白母版，不写公司事实。独立填写工作区：使用者保存的原始资料，未审阅项仍待确认。references/companies/<公司标识>：用户确认摘要后才生成的公司、业务、视觉、来源、就绪范围和单产品记录。references/categories/<类目标识>：真实页面核实后才生成结构，不能填某公司的品牌和价格。

通用包不带真实companies、实际categories、填写副本、图稿或演练数据。两Skill复用同主体资料时核对版本和授权；换公司不能继承旧事实。


## 7. 各程序到底实现到哪里

| 程序 | 已实现 | 边界 |
| --- | --- | --- |
| scripts/init_workspace.py | 新建独立填写副本与ZIP，直接交使用者 | 不覆盖母版和已有材料，不判资料齐全 |
| scripts/save_profile.py | 按用户确认记录写公司参考并读回 | 不解析任意附件；已有参考不自动覆盖 |
| scripts/prepare.py | 基础事实、来源类型、冲突与SKU复核 | 不验证页面结构与来源真实性 |
| scripts/build_plan.py | 真实类目字段与属性的本地映射计划 | 不包含浏览器填写或旧manifest直接适配 |
| scripts/image_inventory.py | 成品命名、顺序、映射、解码及哈希 | 不确认图片实际身份、效果或上传结果 |
| subskills/price-filler/scripts/prepare_pricing.py | 检查确认报价、数量和阶梯 | 不计算缺失报价、换汇或写平台 |


## 8. 主控怎样把内容和图片接起来

用户填写副本 → 原文件实际读取 → 类目结构与同SKU事实 → 用户确认与参考存档 → 标题／卖点／价格子任务及视觉任务 → 字段计划与图片模块清单 → 主控汇总复核 → 真实页面操作。原始照片保留原名；确认成品按单产品交接，主图m1起、详情d1起，由映射清单确定模块和顺序，不猜历史页面ID。

缺失事实、页面必填或未知控件阻断受影响环节；没有选填稿件继续不依赖它的工作，没有证明素材关闭相应展示。未知与冲突不被自动改为确认；任何局部失败都要进最终结果，不能只打印“完成”。

## 原生视觉版的变化

上品仍使用本地模板／参考／字段辅助工具。商品视觉改成单一原生图像生成入口：没有Python、SDK、渲染模板或外部接口。直接给随包空白模板，也接受用户现有产品库；主图和详情内容按真实B端采购信息重新组织，不给旧公司与旧类目板块。

独立生图入口直接交付随包的空白TXT模板ZIP，用宿主文件能力整理参考资料，不调用任何Python或其他渲染程序；前文init_workspace/save_profile是上品侧辅助脚本。
