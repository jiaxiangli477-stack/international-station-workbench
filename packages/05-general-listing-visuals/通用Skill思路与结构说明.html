01 / 使用入口：直接给出可填写模板

读取上品SKILL
→
导出填写副本与ZIP
→
直接给使用者链接
→
填写、放资料并保存

这是入口必须实际做的动作，不是让使用者自己去找assets。首次、换公司或无有效配置时运行 scripts/init_workspace.py，返回真实的文件夹、ZIP和说明路径；空白母版不被修改，已有材料不覆盖。

统一读取与核对
→
集中缺口表与摘要
→
用户确认
→
保存公司参考并读回

确认后由Agent组织内部数据，运行 scripts/save_profile.py 存档。使用者只填资料模板，不需要写JSON。已有同公司有效配置优先复用。

03 / 四个上品sub skill：输入、参考、输出

入口
subskills/title-scout/SKILL.md

references/title-rules.md

subskills/price-filler/SKILL.md

读哪些参考
references/pricing-rules.md；references/quote-input.template.json

入口
subskills/image-upload/SKILL.md
何时调用

主控传入

../../references/image-handoff.md；references/upload-gates.md
返回主控

子Skill不等于自动启动的subagent。由主控或其授权的代理读取这些入口执行任务；目录存在不代表额外模型或平台自动化已经启动。所有候选与计划都回主控汇总。

04 / 上品references逐文件分工

文件名读取时机执行作用
template-delivery.md首次／换公司入口调用模板导出脚本、直接给具体文件链接；用户保存并交回后，确认再入库。
company-onboarding.md发模板时及收到材料后一次性清单、原模块需要哪些资料、集中缺口反馈、必备和选填。
category-page-intake.md建立新类目配置前发布页URL、分区截图、展开属性、搜索型下拉与联动的证据要求。
category-fields.template.json整理页面结构时空白字段结构：key、标签、控件、必填、选项、限制、依赖与证据；默认不确认。
company-profile.template.md用户确认摘要后公司参考的整理框架，不是预填公司事实。
product-evidence.md读取当前产品资料时按实际类目记录值、单位、适用条件、来源、状态与冲突。
input-schema.md主控分派子任务时公司、单SKU、页面字段和各子模块的输入输出契约；草稿不可自动转确认。
input.example.json组织基础复核输入时只有空白输入结构，具体公司名、产品名、报价和类目均不预填。
compliance-review.md生成前与汇总交接前主体、SKU、证据范围和图文交易的一致性；风险与缺口怎样处置。
local-experiment.md运行本地程序时完整输入、各脚本状态、支持限制与未实现的平台执行边界。
image-handoff.md接收视觉成品时单SKU成品目录、文件名、详情模块映射、顺序与图片检查范围。

05 / 商品视觉references逐文件分工

视觉侧按references分流，保留品牌、主图、详情、场景、图中文字和逐图质检的工作方法；没有虚构另一个subskills目录。

文件名读取时机执行作用
template-delivery.md首次视觉入口若上品主控已给模板则复用；单独使用时实际生成填写副本并按确认存档。
company-onboarding.md首次资料配置只索取一次已有资料，明确素材、品牌和模块的证据缺口。
company-profile.template.md确认后建立公司资料具体品牌和能力使用后才保存，不进入空白通用包。
category-page-intake.md确认页面图片模块页面实际允许什么模块、格式和限制，不能套历史数字ID。
category-fields.template.json记录页面规则按需记录结构，默认空值和未核实状态，不代表已适配。
brand-tokens.md定视觉方向前Logo、颜色、字体、层级和留白怎样从公司资料形成规则，不预填旧配色。
main-images.md做主图时逐图目的、SKU、源照片、事实、文案、尺寸、待确认与审核状态。
detail-page.md做详情页时按采购问题选择内容主题，映射实际页面，不凑固定块数。
scene-swap.md处理场景或实物素材时真实／概念／参考三种素材的边界，关键结构与标签保真检查。
copy-compliance.md排版前和导出后图片文字与事实来源、图文一致性和风险处理，不假称OCR已运行。
visual-review.md交成品之前逐张实际看图、同款核对、文字和页面要求检查，失败与待验项分别记录。
image-handoff.md交上品主控时成品文件、详情用途、顺序与检查状态；不把文件通过当上传成功。

06 / 三种存储，只有确认后才入参考库

空白母版

assets/intake-folder-template/

只有准备说明和空字段，供反复复制。

用户填写工作区

填写状态、放原资料并保存；未审阅内容仍待确认。

公司专属参考库

references/companies/<公司标识>/

确认后保存主体、业务、视觉、来源、就绪状态和单产品记录。

真实类目结构核实后另存 references/categories/<类目标识>/，公司规则引用其版本。公司值不能混入通用类目结构，产品值不能当全公司的默认值。

公开通用包不附实际公司库、类目配置、填写副本、成品或演练数据。

07 / 哪些是真程序，哪些是工作规则

程序已实现动作不可据此认定
scripts/init_workspace.py新建独立填写副本与ZIP，直接交使用者不覆盖母版和已有材料，不判资料齐全
scripts/save_profile.py按用户确认记录写公司参考并读回不解析任意附件；已有参考不自动覆盖
scripts/prepare.py基础事实、来源类型、冲突与SKU复核不验证页面结构与来源真实性
scripts/build_plan.py真实类目字段与属性的本地映射计划不包含浏览器填写或旧manifest直接适配
scripts/image_inventory.py成品命名、顺序、映射、解码及哈希不确认图片实际身份、效果或上传结果
subskills/price-filler/scripts/prepare_pricing.py检查确认报价、数量和阶梯不计算缺失报价、换汇或写平台
商品视觉 scripts/render.py真实照片等比例中性预览不是完整主图或详情渲染器

08 / 两个分支怎样汇合

公司与类目确认资料 + 当前SKU事实
               ↓
   ┌───────────┴───────────┐
   ↓                       ↓
上品内容与交易           商品视觉
属性／标题／卖点／报价    品牌／主图／详情／质检
   └───────────┬───────────┘
               ↓
同SKU字段计划 + 成品文件 + 明确模块顺序 + 来源与待验项
               ↓
真实页面填写、上传、授权保存和回读
               ↓
按明确授权发布并核验最终状态

子任务不各自重新索取资料。主控统一核对图文、规格、报价和包装的主体与版本；错误、跳过和待确认项都要进入交接结果。

09 / 当前还有哪些没完成

模板导出、确认参考保存和本地计划工具已有实现；内容与视觉参考可供Agent执行。通用浏览器填写、上传、草稿保存与回读，完整视觉模板、场景与批量制作仍需迁移和现场验证。

不能把新写的reference、生成的候选或本地ready状态说成平台已经操作成功。
