# 新类目：先核实发布页，再索取属性值

## 为什么先收页面证据

商品资料说明“产品是什么”，发布页说明“平台需要填什么”，两者不可互相替代。原包 references/collaboration-sop.md、scripts/inspect_selectors.cjs、categories/*/config.json 都体现了页面字段及选项探查。本规则保留这个顺序，但不继承旧公司的值、行业字段或未经核实的选项。

## 完整准备清单中的页面资料说明

“请在阿里巴巴国际站打开商品发布页，选好这款产品的具体类目，把选好类目后的发布页链接发给我。再给我这页的商品属性截图：先展开‘其他属性／更多属性’，从上到下分段截图，保留字段名称、必填标记和输入提示；下拉字段请展开截图，搜索型下拉再搜一下你产品对应的关键词，把结果也截上。我先确认页面需要哪些资料，再向你补问。”

如果已获授权且可以直接读取用户打开的真实页面，Agent 自行观察并保存页面证据，不要求用户重复截图；无法读取或关键选项不完整时，才请用户补相应截图。只读探查不等于获准保存或发布。

以上内容应与公司、产品及图片资料一并列在首次准备清单中；不要等类目回复后再单独追加一轮索取。收到资料后再按以下要求核验。

## 页面材料怎样提供

1. 选好类目后的真实发布页 URL，以及页面显示的完整类目路径；catId 能从该 URL 或真实页面可靠提取就自行记录，无需用户另填。没有参数时不猜造 catId。不要发登录链接、Cookie、Token或带凭据的完整参数，保存参考前去掉会话或身份参数，记录必要的类目标识。
2. 页面按区块截图：基础／商品属性（含折叠区域）、自定义属性、销售与价格阶梯、发货及包装物流、详情／FAQ等实际存在的区块；平台标记必填的提示、单位、字符上限也要看清。不强行要求页面不存在的模块。
3. 单选、多选、搜索型下拉分别展开；对当前产品所需值进行搜索，必要时滚动或处理联动。保留选项原文、是否可自定义、单选或多选。默认出现几项只记为已观察到的部分选项，不能声称完整，更不能直接推断其他值不存在。
4. 记录页面状态：核查日期、语言、表单版本／模式、折叠区是否展开、前置选项及联动、已观察范围和仍未知部分。截图不能证明控件选择器或程序化写入方式；控件与读回行为需实际页面测试。

## 由 Agent 建立类目配置

将可复用页面结构放在当前 Skill 的 references/categories/<类目标识>/ 下，按实际内容生成：
- category.md：类目名称、路径、必要的 URL／类目标识、核查日期和覆盖范围。
- fields.json：字段名称、所在区块、控件类型、必填／条件必填／可选／未知、单位／限制、字段依赖、已观察到的选项、允许自定义情况和证据引用。格式见 category-fields.template.json。
- evidence.md：页面或截图来源与位置、搜索关键词、尚未核实项。原截图保存在用户授权的 D/E 目录，不打入通用分享包。

公司专属目录的 category-rules.md 指向所用类目配置及版本；不得把某公司品牌、产能、认证、价格等值混进类目通用结构。

字段清单整理后，让用户核对仍有歧义的项目，不要求用户重填整个表格。页面部分未知不伪装为完整配置；执行到依赖未知内容的字段前，先补页面证据。

## 再按实际字段索取产品资料

把页面字段与公司资料、产品规格逐项对应：已找到的直接提取，缺少的具体问。例如“页面中的‘材质’为必填，你现有资料未写，请提供该产品材质”；下拉值只能从页面已核实选项或已证实的自定义机制确定，不能按近义词强选。

价格区间、数量单位、规格组合、发货期、物流和详情限制同样以当前类目页面为准。检查最终页面值和来源一致性后，才能说字段填写通过。首次类目现场适配与核验尚未完成时，不能把参考文件写完说成自动上品已完成。

## 已有配置怎样复用

先核对同一类目、表单版本与关键字段；有变化或选项不匹配，补查相关区块并更新来源和日期。已有配置不是平台永久事实，不需要每次让使用者重交整页截图。

实验校验：成品交接按image-handoff.md。本地校验输出不是平台填写完成证据；必须继续核验真实页面和最终状态。
