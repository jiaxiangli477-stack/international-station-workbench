# 主图与详情图命名、顺序及交接

## 原始素材与成品图分开

资料模板中的产品实拍属于原始素材，不强制改名，不自动当成已审核上架成品。制作并确认后，一款产品一个独立目录，建议：

成品图片/<产品标识>/
  主图/m1.png
  主图/m2.png ... 主图/m6.png
  详情页/d1.png
  详情页/d2.png ... 按需要递增
  detail-map.json

以上是本地工具约定，不是声称国际站所有类目都固定六张主图或固定数量详情图。页面可上传数量、尺寸、文件体积及模块以当前页面为准。不要凑图；主图以m1起按1至6连续编号，本工具超过6需先调整已核实规则再使用；扩展名小写PNG优先，也可JPG/JPEG，文件实际格式必须对应。

只有确认的成品放进这两个目录；预览、草稿、产品原图、不同SKU、不同导出版本另存其他位置。主图不使用m01、m1-final、m1.draft、m1@2x、m10等名字；不能同编号保留PNG和JPG两个版本。不要同时存在“主图”和“main”等候选目录。

## 详情页不要只凭名字猜用途

d1、d2只是文件标识，具体内容与发布页模块必须在detail-map.json逐项写明：

{
  "d1.png": {"module": "当前页面实际模块名称", "order": 1, "source": "该模块的页面或截图证据位置"},
  "d2.png": {"module": "当前页面实际模块名称", "order": 2, "source": "对应证据位置"}
}

顺序用不重复、从1开始连续的整数；可以多张对应同一真实模块。module以用户当时页面为准，不能套用旧行业模块数字ID。d10等可以由本地新清单处理，但不代表旧上传器识别它。图片清单由Agent生成，使用者不需要手填JSON。

旧包存在d1、d2/d3、d4/df、d5/d8/d9、d6/dc/drev、d7和dfac等固定分组；只在针对旧页面受限兼容时有意义。本地检查也识别这些别名，但仍必须有明确映射；不会自动沿用历史模块语义。旧上传器有独立审查报告中的CLI、排序及静默漏图问题，未经修复及当前页面验收不能直接拿来上传新包。

## 本地图片检查

在配套上品Skill运行（绝对路径或进入该目录）：
python scripts/image_inventory.py --image-dir <产品成品图根目录> --product-id <同一SKU标识> --mapping <detail-map.json路径> --output <D/E盘图片清单.json>

校验名称、目录冲突、序号、映射、解码、全透明及实际格式，记录尺寸和SHA256。主图按整数顺序；未映射详情、损坏文件、草稿、缺图会报错，不静默跳过。

输出ready_for_local_review只表示文件和清单检查通过，uploaded始终为false，visual_review和sku_identity_review仍为pending。它不能证明照片内容属于该SKU、是否有乱码、页面支持该模块或上传保存成功；这些需人工／Agent看图及现场回读。尺寸已记录，文件体积需另查；是否符合页面要求需继续核对。

本工具尚未实现真实上传器；禁止把图片清单检查通过当作已上传。
